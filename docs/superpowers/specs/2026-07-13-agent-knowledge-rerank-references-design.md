# Agent 知识库联合检索、Rerank 与参考文档设计

## 目标

优化 Agent 关联多个知识库时的检索和回答行为，使搜索范围、最终排序和用户可见来源保持一致且可解释：

- 多个关联知识库形成一个联合候选池。
- Rerank 由 Agent 配置，不再由知识库配置。
- 知识库召回测试只展示最终相似度得分。
- 用户回答不展示 `[1]`、`[2]` 等切片下标，也不暴露内部文档或切片 ID。
- 召回片段证据不足时，Agent 继续读取原文核验。
- 日志明确记录一次搜索实际覆盖的知识库和排序路径。

## 搜索范围

Agent 配置中的 `knowledge.kb_ids` 是 `knowledge_search` 的默认联合搜索范围。一次搜索会在这些知识库的全部可查询切片中召回候选结果，并在服务端逐个执行用户权限校验；无权限、已删除或不可查询的知识库不会进入搜索。

模型显式传入 `kb_ids` 时沿用现有优先级，以显式范围为准并继续执行用户权限校验。Agent 未关联任何知识库且模型未显式指定范围时，维持兼容行为：搜索当前用户可访问的全部知识库。Agent 关联范围是否升级为强制授权边界不属于本次改动。

日志应记录解析和权限过滤后的实际范围，而不只记录模型的原始参数。至少包含：

- query
- requested `top_k`
- resolved `kb_ids`
- candidate count
- rerank enabled/model
- final result count
- fallback reason（如有）

日志示例：

```text
Calling tool knowledge_search with args: {'query': 'turbox', 'top_k': 10, 'resolved_kb_ids': ['kb_a', 'kb_b'], 'rerank': 'agent/rerank-model'}
```

## 联合召回与 Agent Rerank

所有参与搜索的知识库先形成统一候选池，再进行一次全局排序。候选池大小由 Agent 的知识配置控制，并保证不小于最终 `top_k`。不同 embedding 配置的知识库按兼容配置分组生成查询向量和候选结果，再合并为统一候选池，避免使用第一个知识库的 embedding 配置处理全部知识库。

Agent 的知识配置增加 rerank 设置：

- `enabled`
- `model`
- `top_n` 或候选池大小

当 Agent 配置了可用 reranker 时，服务对联合候选池执行一次统一 rerank，最终返回全局 `top_k`。最终排序分数是 rerank relevance score。

Agent 未配置 reranker 时，直接使用召回引擎产生的最终相似度得分做全局排序。Reranker 调用失败时也回退到相似度排序，同时输出 warning 日志；搜索仍应返回可用结果。

知识库现有的 rerank 配置和管理界面应移除或迁移到 Agent 配置，避免出现两个配置来源。读取旧配置时不得再影响 Agent 问答排序。

## 召回测试

知识库召回测试是单知识库、无 Agent 上下文的诊断工具，因此不执行 Agent rerank。

页面只展示每条结果的最终得分和最终排序，不再分别展示：

- 向量得分
- 关键词得分
- 混合排序分项
- Rerank 得分

“最终得分”表示当前召回模式用于排序的相似度得分。API 可以继续在内部保留诊断字段以兼容其他调用方，但召回测试 UI 不再展示这些分项。

## 工具结果与证据升级

`knowledge_search` 的工具结果仍可携带 `document_id` 和 `chunk_id`，供 Agent 后续调用 `view_file`、`grep_file` 定位原文；这些内部标识不得被复制到用户回答。

Agent 提示采用以下证据升级规则：

> 当召回切片仅提供相关线索，但内容不完整、上下文不足或不足以支撑确定结论时，应继续调用 `view_file` 定位并阅读原文上下文；必要时结合 `grep_file` 查找精确术语。只有在证据充分后再作答，不得根据孤立切片推测。

该规则只在片段不足、存在歧义或需要确认细节时触发，不要求每次召回都读取全文。

## 用户可见参考文档

`knowledge_search` 不再要求模型使用 `[n]` 或切片序号引用。最终回答在正文后提供本地化的“参考文档”或 “References” 区域：

- 按文档去重，同一文档命中多个切片只展示一次。
- 有可访问 HTTP/HTTPS URL 时展示文档标题和链接。
- 没有可访问 URL 时只展示文档标题。
- 不展示 `document_id`、`chunk_id`、切片序号、内部文件路径或不可访问 URI。
- 标题和 URL 必须来自检索结果或后续原文读取结果，不得生成或猜测。

示例：

```markdown
参考文档

- [TurboX 使用指南](https://example.com/turbox)
- 内部部署说明
```

## 数据流

1. Builder 将 Agent 关联的 `kb_ids` 和 Agent rerank 配置写入当前工具作用域。
2. `knowledge_search` 解析模型参数、Agent 默认范围和用户权限，得到实际 `kb_ids`。
3. 检索服务从实际范围生成统一候选池。
4. 有 Agent reranker 时统一 rerank；否则按最终相似度排序。
5. 工具向模型返回排序后的片段、标题、来源和内部定位 ID。
6. 证据不足时，模型调用 `view_file` 或 `grep_file` 读取更多原文。
7. 模型生成回答，并在末尾按文档去重列出标题和可访问链接。

## 错误与边界情况

- 关联知识库全部无权限或不存在：返回无可用知识库的明确消息，并记录 resolved `kb_ids` 为空。
- 某些知识库不可访问：过滤这些知识库，继续搜索其余知识库，并记录过滤数量。
- Reranker 未配置：正常使用相似度排序，不视为错误。
- Reranker 配置无效或调用失败：记录 warning，回退相似度排序。
- 文档标题为空：使用稳定的“未命名文档”本地化文本，不使用内部 ID 代替。
- 来源不是 HTTP/HTTPS URL：只展示标题。
- 同一 URL 或同一文档命中多个切片：用户可见参考文档只保留一项。
- 搜索无命中或证据不足：明确说明知识库没有足够信息，不猜测答案。

## 测试策略

后端测试覆盖：

- 多个 Agent `kb_ids` 形成一个联合候选池。
- 显式 `kb_ids` 保持现有优先级，并继续受用户权限约束。
- 用户权限过滤仍然生效。
- Agent reranker 对联合候选池只调用一次，并回写最终排序分数。
- 未配置或 rerank 失败时按相似度排序。
- 日志包含 resolved `kb_ids` 和排序路径。
- 工具提示不再要求 `[n]` 引用，并包含证据升级规则。

前端测试覆盖：

- 召回结果只展示最终得分。
- 不渲染向量、关键词、混合和 rerank 分项得分。
- Agent 设置页可配置 rerank 模型和候选池参数。

端到端行为检查覆盖：

- 多切片命中最终只生成一个参考文档条目。
- HTTP/HTTPS 来源展示标题和链接。
- 无可访问 URL 时只展示标题。
- 最终回答不包含 `[1]`、`document_id` 或 `chunk_id`。
